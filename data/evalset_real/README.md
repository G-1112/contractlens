# 真实合同评测集（人工标注）

> ⚠️ **本目录当前为空，这是刻意状态。**
> 现有 `data/evalset/` 的 50 份样本全部由 `scripts/build_evalset.py` **程序合成**
> （规则库关键词套用句式模板），标注由构造过程确定，F1 0.9597 反映的是规则覆盖
> 与自洽性，**不代表真实业务分布**。本目录用于接入真实合同，**不得用合成样本占位**。

## 为什么必须真实

| 问题 | 合成集表现 | 真实集预期 |
|---|---|---|
| 规则误报（FP） | 21 个 FP 全部来自 `llm_only`（mock 启发式） | 真实长尾条款会显著抬高 FP |
| 缺失项检测 | 合成模板刻意留空，召回率 0.9928 偏乐观 | 真实合同缺失项更不规律 |
| 风险分级 | 由构造时的level 直接写入 | 需人工判断，边界模糊 |
| 对外引用 | 必须标注「合成样例」 | 可作为可信度证据 |

## 接入流程

```bash
# 1) 放入真实合同（.docx / .doc / .pdf / .txt）到 contracts/
#    建议 ≥20 份，覆盖 5 类合同，且来源分布真实（不要全部来自同一份模板改写）

# 2) 生成标注模板（自动复用pipeline.parse_file 的切分逻辑，口径与审查一致）
python scripts/annotate_real.py --init

# 3) 逐份交互标注
python scripts/annotate_real.py --interactive <文件名>

# 4) 校验：来源登记齐备 + 标注完整 + 等级与风险类型自洽
python scripts/annotate_real.py --validate

# 5) 跑评测，报告写到 docs/eval-accuracy-real.md（与合成集报告分开）
python scripts/evaluate_accuracy.py --evalset data/evalset_real
```

## 数据来源登记（强制）

`--validate` 会拒绝任何**未在 `provenance.json` 登记来源**的文件——这条约束是
为了防止把合成样本当成真实样本充数，也是评审时最容易被追问的点。

登记字段：

| 字段 | 说明 |
|---|---|
| `source` | 来源（公开链接 / 发布机构 / 他人授权等） |
| `obtained` | 取得方式与日期 |
| `license` | 授权与可公开性判断 |

> 若某份合同来自他人提交或含真实当事人信息，**必须脱敏或取得授权**再入库，
> 并在此注明。演示视频与 PPT 同样受匿名评审约束（见 `docs/脱敏扫描报告.md`）。

## 对外引用口径

引用真实集指标时必须同时给出：**样本量、合同类型分布、来源构成**。样本量 <30
份时置信区间很宽，不要单点宣称「准确率 XX%」。
