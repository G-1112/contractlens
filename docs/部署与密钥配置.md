# 部署与密钥配置说明

> 面向两种场景：**本地自建**与**公网部署（带真实 LLM）**。
> 现状：公网实例已挂DeepSeek Key，评审可直接看到 `mode=llm` 的真实判定。
> 更新日期：2026-10-20

---

## 一、配置方式

项目支持**两种**注入方式，优先级为「环境变量 > `.env` 文件」。

### 1. 环境变量（推荐用于 CI / 容器）

```bash
export LLM_API_KEY=sk-xxxxxxxx
export LLM_BASE_URL=https://api.deepseek.com
export LLM_MODEL=deepseek-chat
```

PowerShell：

```powershell
$env:LLM_API_KEY="sk-xxxxxxxx"
```

### 2. `.env` 文件（本地开发）

复制模板并填写：

```bash
cp .env.example .env
```

`.env` **已在 `.gitignore` 中**，不会被提交入库（`git check-ignore -v .env` 可验证）。

### 3. 全部相关变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `LLM_API_KEY` | 空 | 模型 Key。空 → 自动降级为 mock 离线模式，功能不中断 |
| `LLM_BASE_URL` | `https://api.deepseek.com` | OpenAI 兼容端点（可换通义/智谱等） |
| `LLM_MODEL` | `deepseek-chat` | 模型名 |
| `LLM_TEMPERATURE` | `0` | 采样温度 |
| `LLM_MAX_RETRIES` | `2` | 失败重试次数 |
| `LLM_TIMEOUT_SECONDS` | `60` | 单次调用超时 |
| `LLM_CONCURRENCY` | `8` | 条款级并发判定上限（性能关键） |
| `LLM_DAILY_BUDGET` | `0`（不限） | **公网必设**。LLM 调用日配额，用尽返回 429，次日自动恢复 |
| `PUBLIC_DEPLOY` | 空 | **保险丝**。置 `1` 强制离线，Key 读都读不到 |
| `REVIEW_ACCESS_CODE` | 空 | 评审访问口令。留空=不启用 |
| `HOST` / `PORT` | `127.0.0.1` / `8000` | 监听地址与端口 |
| `MAX_UPLOAD_BYTES` | `20971520` | 单文件上限（20MB） |

## 二、Key 的读取与注入路径

```
.env 文件  ┐
           ├─► api/config.py::_load_env_file()   os.environ.setdefault（已存在的环境变量优先）
环境变量   ┘        │
                    ▼
            os.environ["LLM_API_KEY"]
                    │
                    ▼
            class Settings._llm_api_key          导入期求值
                    │
                    ▼
            Settings.llm_api_key  (property)    PUBLIC_DEPLOY=1 时短路返回 ""
                    │
                    ├─► llm_enabled  ──► /api/health 的 llm_enabled 字段
                    └─► api/engine/llm_engine.py::_init_client()
                                └─► openai.AsyncOpenAI(api_key=...)
```

**关键设计**：

1. `_load_env_file()` 用 `os.environ.setdefault`，所以**真实环境变量优先级高于 `.env`**，容器里注入即可覆盖文件。
2. `llm_api_key` 是 property，`PUBLIC_DEPLOY=1` 时 getter 直接返回空串——即使目录里存在 `.env` 也读不到、用不了。这是一道防呆保险丝。
3. Key **只存在于内存**，不写入任何数据文件、不进日志、不进 trace。

## 三、启动与对外暴露端口

### 本地

```bash
# 后端（默认 127.0.0.1:8000）
python -m uvicorn api.main:app --reload --port 8000

# 前端（开发态）
cd web && npm install && npm run dev      # http://localhost:5173
```

### 公网（单端口）

前端构建产物由后端**同端口**托管，只需暴露一个端口：

```bash
# 1) 构建前端
cd web && npm run build

# 2) 同步产物（部署平台会排除 dist/，所以另存一份到 site/）
cp -r web/dist/* web/site/

# 3) 发布：平台自动探测 Python 项目时执行根目录的 `python main.py`
#    （入口读取 $PORT、绑定 0.0.0.0、挂载 api.main:app，见 main.py）
```

> ⚠️ 2026-10-21 实测：发布平台对 Python 项目的启动探测是**根目录
> `python main.py`**，不是 `uvicorn api.main:app`。缺根入口会导致
> SITES_START_FAILED，且旧沙箱已被替换、分享链接同时不可用。
> 因此仓库根目录必须保留 `main.py`（tests/test_deploy_entry.py 锁定该契约）。
> 本地开发不受影响，仍用 `python -m uvicorn api.main:app --reload --port 8000`。

等效的手动启动命令（理解用，发布时不需要）：

```bash
PUBLIC_DEPLOY=0 \
LLM_DAILY_BUDGET=200 \
python -m uvicorn api.main:app --host 0.0.0.0 --port ${PORT:-3000}
```

| 要求 | 原因 |
|---|---|
| `--host 0.0.0.0` | 只听 127.0.0.1 则容器外不可达 |
| `--port ${PORT}` | 平台注入 `PORT` 环境变量，端口需与之匹配 |
| **只能暴露一个端口** | 平台只反向代理一个端口；Vite dev server 无法与 API 并存，故用构建产物 |

访问入口：

| 路径 | 内容 |
|---|---|
| `/` | 前端 SPA（构建产物就绪时） |
| `/api/health` | 健康检查，含 `llm_enabled` / `llm_budget_remaining` |
| `/docs` | 自动生成的 OpenAPI 文档 |

## 四、本地调用公网服务

线上地址：`https://contractlens-agent.app.workbuddy.host`

若设置了 `REVIEW_ACCESS_CODE`，所有 `/api/*` 请求需带口令，二选一：

```bash
# 方式 A：请求头
curl -H "X-Review-Code: <口令>" https://.../api/health

# 方式 B：查询参数（方便浏览器直接打开导出链接）
curl "https://.../api/report/<file_id>?format=pdf&code=<口令>"
```

### 完整调用示例

```python
import httpx

BASE = "https://contractlens-agent.app.workbuddy.host"
c = httpx.Client(trust_env=False, timeout=180)   # 注意：trust_env=False，避免代理干扰

# 1) 健康检查（确认 LLM 已启用）
print(c.get(f"{BASE}/api/health").json())
# 期望：{"status":"ok","llm_enabled":true,"llm_model":"deepseek-chat",
#        "llm_daily_budget":200,"llm_budget_remaining":200}

# 2) 上传（multipart/form-data）
with open("data/samples/借款合同样本.docx", "rb") as f:
    r = c.post(f"{BASE}/api/upload",
               files={"file": ("loan.docx", f,
                       "application/vnd.openxmlformats-officedocument.wordprocessingml.document")},
               data={"contract_type": "loan"})
fid = r.json()["file_id"]

# 3) 分析（SSE 流式；POST 会阻塞到流结束）
r = c.post(f"{BASE}/api/analyze",
           json={"file_id": fid, "contract_type": "loan"})
# 事件序列：progress(parse) → progress(rule) → progress(judge)×N
#           → risk×N → progress(score) → done{report}

# 4) 取完整报告
report = c.get(f"{BASE}/api/result/{fid}").json()
print(report["total_score"], report["risk_counts"])

# 5) 导出（GET 即可，前端用的是 <a href>）
pdf = c.get(f"{BASE}/api/report/{fid}", params={"format": "pdf"})
assert pdf.content[:5] == b"%PDF-"

# 6) 追问对话（返回可追溯 sources + 工具轨迹 trace）
ans = c.post(f"{BASE}/api/chat", json={
    "file_id": fid,
    "question": "第4条约定的年利率是否合法？请引用具体法条说明",
}).json()
print(ans["mode"], len(ans["sources"]), len(ans["trace"]))
```

现成脚本：

```bash
python scripts/availability_check.py --label 验证    # 全链路 11 项
python scripts/verify_export_online.py              # 五格式导出
python scripts/e2e_smoke.py <base_url>              # 冒烟
```

## 五、安全注意事项

### 必须遵守

1. **禁止硬编码入库**
   Key 只能来自环境变量或 `.env`。`.env` 已在 `.gitignore`；提交前用
   `git check-ignore -v .env` 复核。CI/容器里用环境变量注入，不落盘。

2. **日志绝不打印完整 Key**
   本项目启动日志只记录 `model`、`base_url`、`key_loaded` 布尔值与 `key_len` 长度：

   ```
   LLM 已启用 model=deepseek-chat base_url=https://api.deepseek.com key_loaded=True key_len=35
   ```

   **不要**在调试时改成 `logger.info(f"key={key}")`——日志会流向平台/第三方。
   排障需要确认「Key 有没有读到」时，看 `key_loaded` 和 `key_len` 足够。

3. **`.env` 会被部署上传**
   ⚠️ 部署平台压缩**整个项目目录**，只排除 `node_modules/.git/构建产物`，
   **`.gitignore` 对它无效**。放在项目目录里的 `.env` 一定会被上传。
   这是公网挂 Key 的必然代价——所以必须同时做好下面两条。

4. **务必设置 `LLM_DAILY_BUDGET`**
   公网无鉴权时，任何人都能触发调用。按 IP 限流在反向代理后会退化为「全局每分钟
   N 次」（所有访客共用代理 IP），窗口一过就放开，挡不住长时间爬取。
   `LLM_DAILY_BUDGET` 是最后一道按天闸门。当前设 **200**。

5. **在模型服务商侧设消费上限**
   代码侧闸门只能限制本服务，**限制不了别人拿你 Key 另作他用**（Key 泄漏时尤其）。
   去 DeepSeek 控制台给该 Key 设月度/日消费上限，并设定告警。

6. **赛后轮换 Key**
   赛事结束后（2026-11-10 提交、12 月总决赛结束）在控制台作废该 Key。

### 建议

7. **需要账号密码时用 `REVIEW_ACCESS_CODE`**，提交平台时把口令作为账号密码填写。
   它是共享口令而非账号系统——项目刻意不引入账号体系，避免采集个人信息。
8. **紧急止损**：把 `PUBLIC_DEPLOY` 置 `1` 重新部署即可立刻断开 LLM，
   服务继续以离线模式运行，功能不中断。
9. 敏感调试信息只落本地日志，不要回传到 SSE 或前端。

## 六、验证方式

### 1. 配置是否生效

```bash
curl https://contractlens-agent.app.workbuddy.host/api/health
```

期望：

```json
{"status":"ok","llm_enabled":true,"llm_model":"deepseek-chat",
 "llm_daily_budget":200,"llm_budget_remaining":200}
```

`llm_enabled=true` → Key 已被读取；`llm_model` 不是 `mock` → 真实 LLM 路径生效。

### 2. 真实调用是否返回结果

```bash
python scripts/availability_check.py --label 验证
```

判据：

| 检查项 | 通过标准 |
|---|---|
| 健康检查 | `llm_enabled=True`且 `model=deepseek-chat` |
| 上传→分析 | 返回条款数 > 0，耗时约 **5~11 秒**（真实 LLM；离线 mock 只要 0.03秒，可据此区分） |
| 追问对话 | `mode=llm`（不是 `mock`），`sources ≥ 1` |
| 注入检出 | `injection_flagged=true` |
| 导出 | 五格式全200，PDF 以 `%PDF-` 开头 |

**最快的单点验证**——追问对话的 `mode` 字段就是 LLM 是否真被调用的铁证：

```bash
curl -X POST https://.../api/chat \
  -H "Content-Type: application/json" \
  -d '{"file_id":"<fid>","question":"年利率上限是多少？"}'
# 期望 "mode":"llm"
```

### 3. 日配额是否生效

连续调用至用尽后：

```bash
curl -i https://.../api/chat -H "Content-Type: application/json" -d '{...}'
# 期望 HTTP 429 + {"detail":"今日演示调用额度已用尽，请稍后再试"}
```

`/api/health` 的 `llm_budget_remaining` 会随调用递减，次日自动恢复满额。
