# 迭代 v1 · 规则优先：先把确定性做到位

## 重构前

最初设想直接"把合同丢给大模型，让它输出风险列表"。问题：

- 输出不稳定，同一份合同两次结果可能不同；
- 无法定位到具体条款；
- "没写维修责任"这类**缺失风险**大模型基本发现不了。

## 重构后

拆出**零 LLM 依赖的规则引擎**，三类确定性检测：

| 检测类型 | 示例 | 说明 |
|---|---|---|
| 关键词匹配 | "押金概不退还" | 含否定检测，避免误报 |
| 数值阈值 | "押金三个月租金" | 提取中文数字+单位后比较 |
| 缺失检测 | 全文无"维修" | 该写没写，文档级扫描 |

规则库 YAML 维护，三类合同约 80 条，每条带 `level / risk_type / explanation`，
**可解释、可追溯、可独立单测**。

## 收益

- 规则层可独立测试，不依赖网络与 API；
- 缺失检测成为差异化能力（纯关键词和 LLM 都容易漏）；
- 为后续双引擎融合奠定"确定性下限"。
