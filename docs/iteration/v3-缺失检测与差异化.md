# 迭代 v3 · 缺失检测与可复现性收口

## 重构前

规则库最初只有"关键词 + 数值阈值"两类，对"合同里**根本没写**某条款"的隐性风险无能为力。
同时，RAG 检索依赖 ChromaDB + 本地 embedding，复现需要下载模型，评委容易卡住。

## 重构后

1. **新增缺失检测（missing）**：`must_contain` 字段声明"必须出现的词"，
   文档级扫描，缺了就报"该写没写"。如：未约定维修责任主体、未缴社保、未约定押金退还时间。

2. **检索器零依赖回退**：默认纯 Python 字符级 bigram TF-IDF（确定性、离线、零依赖），
   ChromaDB + bge-small-zh 作为可选升级，把"10 分钟复现"从口号变成现实。

   > 后续注记（第十四轮）：可选 Chroma 路径实为空壳（假开关），已整体移除；
   > 检索口径统一为"TF-IDF 稀疏向量检索（轻量 RAG）"，全项目仅此一条检索路径。

3. **评分雷达随合同类型适配**：租约=押金/解约/维修/违约/隐私；劳动=工资/试用期/社保/竞业限制/违约金；
   实习=报酬/安全/期限/知识产权/违约金。无法归类项不计入雷达但计入总分，避免误导。

## 收益

- 缺失检测使规则引擎对"隐性条款缺失"的捕获能力显著增强，成为差异化卖点；
- 零依赖回退保证评委离线也能跑通全流程；
- 雷达维度语义化，五维雷达真正反映该类合同的风险结构。
