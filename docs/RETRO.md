## 二、关键决策与取舍

### 决策 1：做"流水线"而非"聊天框"
通用 AI 聊天工具能读合同，但输出大段文字、无法定位条款、不会告诉你"怎么写回去"。
因此定位为：解析 → 切分 → 双引擎判定 → 可视化 → 修订稿的**文档处理流水线**。

### 决策 2：双引擎融合（规则 + LLM）
纯规则覆盖不全语义，纯 LLM 不稳定且黑盒。用规则抬高风险下限、LLM 补语义，
并在 UI 上区分来源，不冒充权威。详见 `docs/技术文档.md` 第二章。

### 决策 3：缺失检测作为差异化
"该写没写"（如未约定维修责任、未缴社保）是纯关键词和 LLM 都容易漏的场景，
只有确定性扫描能稳定捕获。这成为规则引擎最独特的一类规则。

### 决策 4：纯 Python TF-IDF 检索器（唯一检索路径）
为保证 10 分钟复现，法规检索用字符级 bigram TF-IDF 稀疏向量（零依赖、离线、确定性），
不引入外部向量库与 embedding 模型，避免评委复现时卡在模型下载。

## 五、经验沉淀

1. **能确定性计算的，绝不交给模型**——语速、缺失条款、数值阈值这些交给规则更准更便宜；
2. **约束模型输出结构，而不是靠自然语言祈祷**——JSON Schema + Pydantic + 原文照抄证据；
3. **降级不是锦上添花，是刚需**——LLM 挂了系统还得能用，这是可信度的底线；
4. **复现优先于炫技**——每个重依赖都留了零依赖回退，评委才能在 10 分钟内跑起来。
