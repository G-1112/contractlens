# Prompt 链 013 · 风险判定门槛（区域赛收敛迭代）

> 日期：2026-11-24。对应代码：`api/engine/llm_engine.py` `_SYSTEM_PROMPT`（v13）。
> 实证依据：`docs/iteration/regional_v2/收敛迭代报告.md`。

## 起因

真实 LLM 口径首测（23 份合同 / 439 条标注条款）：R 0.9792 打满，但 P 只有
0.3570——模型把中性程序性条款（通知方式、不可抗力、合同份数、文本解释）
和保护性条款（"不得向丙方收取实习押金"）也标成中/低风险。逐条人工核对
dev 组 131 个 FP 后归纳：模型没有"风险门槛"概念，把"可以点评"当成"应该报险"。

## 改动

系统 Prompt 新增【风险判定门槛 · 优先级最高】：

1. 判定前先问"这一条会不会让乙方（弱势方）实际吃亏"；
2. 四类一律填"无"：中性程序性 / 保护性 / 法定权责常规表述 / 纯格式性空白；
3. 四类应当报出：风险分配型空白（违约金比例、罚息上浮、维修承担方）、
   不利送达（"视为送达"）、单方权利、开放式责任；
4. 拿不准填"无"（宁缺毋滥，精度导向的产品决策）。

## 实测效果（dev 组）

| 版本 | P | R | F1 |
|---|---|---|---|
| v12（无门槛） | 0.3515 | 0.9595 | 0.5145 |
| v13（有门槛） | 0.6421 | 0.8243 | 0.7219 |

holdout 盲测 F1 0.7101，与 dev 一致，未过拟合。

## 教训

提示词里"不要编造法条"这类否定式约束模型执行得很好，但**没有说清"什么
才算风险"时，模型的默认行为是把一切可讨论的条款都报出来**。评测驱动的
提示词迭代必须先做 FP 逐条归因，再定义边界——直接凭感觉加约束只会来回震荡。
